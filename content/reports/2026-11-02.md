## 今天的主线

如果把今天的热榜按「大家在想什么」分类，最集中的一条是 **让 AI 学会「少干活」**。

过去的思路是：模型不够强，就上更大的模型、更长的思维链、更多的 Agent 并行。今天两篇最高赞的论文都在反驳这个方向。R²Orch 讲的是一个 Agent 调度员该怎么练习「分配任务」——它用自博弈（自己出题、自己考、自己判分）来自我进化，还会主动「撤掉技能」：当某个技能撤掉以后发现成绩没下降，说明这个技能已经被内化成了模型的本能，就该删掉了。清华那篇更直接：它提出让一个轻量的「直觉层」（System-1）先判断哪些操作值得做，再交给重量级的「思考层」（System-2）去执行，论文给出的公式表明**执行量可以按「有用交互密度」的倒数下降**。

换算成一句人话：**未来 AI 的进步，可能不是「算得更多」，而是「算得更准」——把算力花在真正有用的那一步上。**

第二条主线是 **Agent 的记忆与上下文**，这在 GitHub 上体现得最明显：`claude-mem`（+1799）、`paperclip`（+507）、`mattpocock/skills`（+970）都在解决同一个问题——Agent 每次开新会话就像失忆，得靠外部系统把「上次干过什么」存起来再喂回去。这条线跟你正在做的第三章项目是同一个战场。

第三条是 **视频/世界模型成了新的基础设施**：腾讯 Wizard 把「游戏世界」做成可实时操控的视频生成；FrameForge 拿视频模型的先验去做图像生成；HiFOR 让机器人先预测未来状态再决定动作。共同点是：**视频模型不再只是「生成好看的画面」，而是变成了可以反复试错的模拟器。**

## 一、Hugging Face Daily Papers

### 1. R^2Orch: Recursive Self-Improvement for Agent Orchestration via Self-Play within a Skill-Internalization Loop

`2610.22740` · Chinese University of Hong Kong, Shenzhen · ▲ 65 赞 · 提交日 2026-11-02

**说人话：** 这篇论文教 AI 里的「调度员」（负责决定该派哪个工具、哪个子 Agent 去干活的角色）怎么通过自己跟自己对练变强。它有两个创新：一是让 AI 自己出题，但出的题必须满足「随着技能被陆续撤掉，这道题的结果依然有悬念」；二是「技能撤回」机制——当撤掉某个技能后成绩没变差，就说明这个技能不用再单独调用了。最终目标是「零技能部署」：所有本事都内化进模型本身。

**为什么值得看：** 这是今天 HF 点赞最高的论文（65 赞），而且方向很关键：过去多 Agent 系统全靠人手写「什么时候该调用谁」的规则，这篇试图让模型自己学出来。如果你是做 Agent 的，这篇代表的是「orchestration 自动学习」这个正在起势的方向。

**打个比方：** 像一个厨师带学徒：学徒一开始每道菜都要翻菜谱（技能），练熟以后菜谱可以收起来（技能撤回）——如果收起菜谱还能做对，说明真学会了。而「递归可学习性」就是让出题人专门出那种「翻不翻菜谱结果会不一样」的题，这样练才有意义。

**给小白的一句话提醒：** 论文代码已开源（github.com/beita6969/R2Orch），但它需要多轮 RL 训练，不是拿来即用的工具，更适合看思路。

### 2. Does Scaling Toward AGI Depend on What System-1 Lets System-2 Execute?

`2610.39497` · Tsinghua University · ▲ 56 赞 · 提交日 2026-11-02

**说人话：** 论文问了一个很大的问题：通往 AGI 的下一步，靠的还会是「更大的模型 + 更长的思考」吗？作者的回答是「一定程度上不是」。他们提出让一个便宜的「直觉层」（System-1）先预测每个候选操作值不值得做，只有够格的才交给昂贵的「思考层」（System-2）去执行，执行结果再反过来修正直觉层的判断。

**为什么值得看：** 它给出了一个可量化的结论：当「有用交互的密度」是 ρ 时，执行计算量可以降到接近 1/ρ。换句话说，**决定 AI 成本的不再是总算力，而是「有效算力」（informative compute）**。这个视角对做 Agent 产品的人特别有用——省钱的关键不在于换小模型，而在于少做无用功。

**打个比方：** 像点外卖前的比价：不是每道菜都要亲自下厨试（System-2 很贵），先花一秒看一眼「这道菜值不值得点」（System-1 很便宜），只有通过筛选的才真正下单。筛选器越准，省下的就越多。

**给小白的一句话提醒：** 这是一篇偏理论与框架的论文（清华），没有现成工具；但它提供了一个判断「你的 Agent 哪里在浪费算力」的思维工具。

🔗 [HF 论文页](https://hf-mirror.com/papers/2610.39497) · [arXiv 原文](https://arxiv.org/abs/2610.39497) · [项目主页](https://cheemswang.github.io/blogs/sys1-sys2-codesign.html)

### 3. FrameForge: Harnessing Priors of Video Foundation Models for Unified Image Generation

`2610.36545` · FrameX-AI · ▲ 25 赞 · 提交日 2026-11-02

**说人话：** FrameForge 把视频大模型的能力借来做图像生成。关键观察是：不同任务里「参考图」和「目标图」之间的关系差别很大（有的是换风格，有的是换主体，有的是改光照），而视频模型天生就会表达「随时间变化」这件事。于是它把条件图和目标图放进一段「虚拟时间轴」里，用不同的时间尺度去表达不同的变换关系。

**为什么值得看：** 这是今天图像生成方向最有意思的一篇：与其重新训一个统一的图像模型，不如**把已经学会「变化」的视频模型改造一下**。这反映了一个更大的趋势——视频模型正在变成多模态的通用底座。

**打个比方：** 像剪片子：一段视频天然就在讲「从 A 变到 B」。FrameForge 就是把「修图」重新表述成「从参考图到目标图的一段一分钟短片」，然后让一个懂剪辑的模型去拍。

**给小白的一句话提醒：** 有项目主页可看效果对比图，适合先看图再看文。

🔗 [HF 论文页](https://hf-mirror.com/papers/2610.36545) · [arXiv 原文](https://arxiv.org/abs/2610.36545) · [代码](https://github.com/Lyne1/FrameForge) · [项目主页](https://lyne1.github.io/FrameForge-page/)

### 4. Wizard: Manipulate Any World in Real Time via Agentic Control

`2610.40339` · Tencent · ▲ 24 赞 · 提交日 2026-11-02

**说人话：** 腾讯的 Wizard 想做的事：让用户在一个「可玩的视频世界」里实时操控角色，而且换到没见过的场景、没见过的角色也能用。做法是把「动作」和「画面」解耦——先由 Agent 层用骨架、几何这类结构化数据精确控制角色动作，再由视频生成模型负责把画面渲染得好看。

**为什么值得看：** 这是「世界模型」最落地的一条路：**游戏行业可能最先被改造**。而且它的思路对做 Agent 的人有普遍启发——把「逻辑控制」和「内容生成」拆开，各自用最擅长的技术。

**打个比方：** 像木偶戏：Wizard 是那个提线的人（精确控制骨架动作），视频模型是那个会画背景的画家。提线的人不用会画画，画家也不用懂怎么走路。

**给小白的一句话提醒：** 目前是研究项目，不是能直接玩的游戏；可以关注项目主页的 demo 视频。

🔗 [HF 论文页](https://hf-mirror.com/papers/2610.40339) · [arXiv 原文](https://arxiv.org/abs/2610.40339) · [项目主页](https://wyzardwu.github.io/wizard/)

## 三、今天顺手学的 3 个概念

**自博弈（Self-Play）**：让模型自己出题、自己解题、自己判分，形成一个不需要人类标注的训练闭环。R²Orch 用的就是它——好处是数据可以无限生成，难点是「出的题要有区分度」，否则模型学不到东西。

**System-1 / System-2**：借自心理学的比喻：System-1 是快速直觉（便宜、粗糙），System-2 是慢速推理（昂贵、准确）。今天清华那篇的核心主张是：**别什么都交给 System-2，先让 System-1 筛一遍**。这个模型在你自己的 Agent 里也能用——把「要不要调用大模型」做成一次廉价判断。

**MoE（混合专家）**：一种模型结构：模型里有很多「专家」子网络，但每个 token 只激活其中一小部分。所以总参数可能几百 B，实际计算量可能只有几十 B。今天上榜的 FreeToken 和 colibri 都是在利用这个特性做本地部署——**只把用到的那部分专家加载进内存，其余留在磁盘上**。
